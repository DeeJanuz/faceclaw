# L3: EvenHub root navigation

Status: implemented and verified.

Changed paths:

- `app/apps/evenhub/session.ts`
- `app/apps/evenhub/evenhub-window.ts`
- `tests/evenhub-root-navigation.test.cjs`
- `handoff/L3.md`

Behavior before: legacy `shutDownPageContainer(exitMode=1)` called the
EvenHub window's `focusSwitcher` hook directly, so every such root request
forced the app switcher even when the host navigation policy selected sleep.
The explicit Faceclaw extension method `returnToAppSwitcher` also used that
hook, and real quit / other shutdown modes used their existing close paths.

Behavior after: the window adapter exposes a separate internal
`returnFromAppRoot` hook routed to `shell.returnFromAppRoot()`. Legacy
`exitMode=1` calls that hook and retains the running session. The host then
applies `rootBack=sleep` or `rootBack=switcher`. Explicit
`returnToAppSwitcher` continues to call `focusSwitcher` unconditionally.
`quit` still closes immediately, and other shutdown modes retain their
existing delayed close behavior. No public method signatures or SDK files
were changed.

Verification:

```text
node --test tests/evenhub-root-navigation.test.cjs tests/evenhub-containers.test.cjs
12 passed, 0 failed
```

The focused tests cover root sleep and switcher routes, session retention,
explicit switcher behavior under either root policy, immediate quit, delayed
other-exit behavior, and the separate window-adapter wiring.

Documentation contract rows affected: semantic root-back, explicit switcher,
explicit close/quit, and legacy EvenHub compatibility. The compatibility
statement is host behavior: `exitMode=1` is interpreted as semantic root-back
by this Faceclaw adapter. It is not claimed as an upstream EvenHub SDK
guarantee. The SDK documentation reconciliation remains with L6.

Remaining uncertainty: no physical-device validation was performed, and the
actual Snake wake sequence remains outside this task. The focused tests use
the extracted production methods and source-level adapter wiring checks; they
do not establish firmware behavior or device-side navigation state.
